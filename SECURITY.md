# 安全性政策

[English Version Below](#english-version)

## 支援的版本

我們主要針對 `main` 分支的最新狀態提供安全性更新，並盡最大努力維護之。

## 回報安全性漏洞

如果您在 OpenRing 發現了潛在的安全漏洞，我們懇請您以私下且負責任的方式回報。**請勿**開啟公開的 GitHub Issue，以免漏洞被有心人士利用。

- 📧 Email: security@openring.dev
- 📝 主旨: `[OpenRing Security] <簡短摘要>`

請在信件中包含以下資訊：

- 漏洞的類型與影響範圍
- 受影響的模組或元件
- 重現步驟或是概念驗證 (PoC)
- 建議的修補方案（若您有想法）

## 回報處理流程

我們承諾會採取以下行動：

1. 在 72 小時內確認收到您的回報
2. 評估該漏洞的嚴重程度與潛在影響
3. 著手進行修復，並協調公開揭露的時間
4. 在發布修補程式後，公開安全性建議

非常感謝您協助維護開源社群的安全！

# Security Policy

## Supported Versions

Security updates are provided on a best-effort basis for the latest `main` branch state.

## Reporting a Vulnerability

Please report vulnerabilities privately and responsibly. Do not open public GitHub issues for security vulnerabilities to prevent exploitation.

- 📧 Email: security@openring.dev
- 📝 Subject: `[OpenRing Security] <short summary>`

Include the following information in your report:

- Vulnerability type and impact
- Affected modules or components
- Reproduction steps or proof of concept (PoC)
- Suggested remediation (if known)

## Response Process

We will aim to:

1. Acknowledge receipt within 72 hours
2. Triage severity and potential impact
3. Work on a fix and coordinate public disclosure
4. Publish a security advisory after remediation

Thank you very much for helping to keep the open-source community secure!
